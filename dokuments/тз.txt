# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Веб-приложение «Текст по-человечески»

**Версия документа:** 1.1
**Дата составления:** 24 ноября 2026 г.
**Статус:** Утверждено заказчиком
**Роль аналитика:** Продуктовый аналитик

## 1. Введение

### 1.1. О документе
Настоящее техническое задание (ТЗ) описывает требования к веб-приложению «Текст по-человечески» — анонимному инструменту, помогающему клиентам психологов структурировать сумбурные мысли о личных ситуациях.

### 1.2. Назначение продукта
Приложение выступает в роли «безопасного зеркала»: сохраняет все факты, имена и цифры пользователя, но переформулирует хаотичный текст в чёткую, структурированную общую картину с бережными гипотезами о внутренних процессах человека.

### 1.3. Ключевой принцип
Приложение **НЕ заменяет** профессиональную терапию, **НЕ ставит диагнозы**, **НЕ использует** жёсткие психологические шаблоны. Оно помогает прояснить ситуацию и подготовить запрос для работы с психологом.

---

## 2. Цели и задачи

### 2.1. Цель продукта
Создать анонимный веб-инструмент, который помогает клиентам психологов структурировать сумбурные мысли и вопросы о своей личной ситуации.

### 2.2. Задачи
- Преобразовать хаотичный текст в логически связную общую картину.
- Сформулировать осторожные гипотезы о внутренних процессах.
- Сохранить все факты, имена и цифры без искажений.
- Распознать «красные флаги» и рекомендовать обратиться к специалисту.
- Обеспечить анонимность и приватность пользователя.

---

## 3. Целевая аудитория

**Основная аудитория:** клиенты психологов и люди, работающие над личностными проблемами.

**Характерные особенности:**
- Испытывают трудности с формулированием мыслей из-за эмоциональной заряженности.
- Описывают ситуации сумбурно, хаотично, с излишней детализацией.
- Находятся в процессе самоанализа или подготовки к сессии с психологом.
- Могут находиться в уязвимом или тревожном состоянии.

---

## 4. Пользовательский сценарий (User Journey)

| Шаг | Действие пользователя | Реакция системы |
|-----|----------------------|-----------------|
| 1 | Заходит на главную страницу | Показывает интерфейс с дисклеймером |
| 2 | Читает дисклеймер | Дисклеймер всегда виден, не пугающий |
| 3 | Вводит/вставляет свой сумбурный текст | Поле поддерживает до 5000 знаков, при превышении — блокирует ввод |
| 4 | Нажимает «Структурировать мысли» | Показывает спокойный индикатор загрузки |
| 5 | Получает готовый структурированный текст | Отображает результат + кнопку «Скопировать» |
| 6 | (При «красных флагах») Видит предупреждение | Добавляется блок с рекомендацией обратиться к специалисту |
| 7 | Копирует текст или начинает заново | Текст копируется в буфер / интерфейс очищается |

## 5. Функциональные требования

### 5.1. Структурирование текста
- Преобразование хаотичного ввода в логически связный текст.
- Выделение общей картины ситуации.
- Формулирование 2–4 осторожных гипотез о внутренних процессах.
- Использование модальных глаголов: «возможно», «кажется», «вероятно», «может быть».
- Избегание категоричных утверждений и диагнозов.

### 5.2. Строгое сохранение фактов
- Все имена (собственные) остаются без изменений.
- Все цифры (возраст, даты, суммы) сохраняются точно.
- Все ключевые факты (места, события, люди) не искажаются.

### 5.3. Детекция «красных флагов»
Система распознаёт маркеры:
- Суицидальные мысли или намерения.
- Самоповреждение.
- Острый кризис.
- Насилие.

При обнаружении:
- Генерация текста продолжается (не прерывается).
- К результату добавляется блок предупреждения.
- Возвращается флаг `hasRedFlags: true`.

### 5.4. Отсутствие редактирования
- Пользователь **НЕ может** редактировать сгенерированный текст.
- Доступны только действия: «Скопировать» и «Начать заново».

### 5.5. Копирование в один клик
- Используется Clipboard API.
- После копирования — краткое уведомление (toast) «Текст скопирован», исчезает через 2 секунды.

### 5.6. Ограничения ввода
- Максимальная длина текста — **5000 знаков**. Ввод и вставка длиннее лимита блокируются на стороне интерфейса.
- Рядом с полем ввода отображается счётчик знаков (например, «1240 / 5000»).
- Минимальная длина для отправки — 10 знаков (защита от случайных и бессмысленных запросов).
- Backend повторно проверяет лимит: запросы длиннее 5000 знаков отклоняются с кодом `400` и понятным сообщением.

### 5.7. Обработка ошибок LLM
- **Таймаут:** если ответ LLM не получен за 30 секунд, запрос прерывается, пользователь видит вежливое сообщение: «Не удалось обработать текст. Попробуйте ещё раз.» с кнопкой повтора.
- **Повторные попытки (retry):** при ошибке API или таймауте backend выполняет до 2 повторных попыток с экспоненциальной задержкой.
- **Битый JSON:** если LLM вернула невалидный JSON, backend выполняет один повторный запрос с ужесточённой инструкцией формата; при повторном сбое извлекает текст из «сырого» ответа (fallback) либо показывает сообщение об ошибке.
- **Логирование ошибок:** все сбои LLM логируются на backend (без текста пользователя) для отладки.

## 8. Входные и выходные данные

### 8.1. Входные данные
- Обычный текст на русском языке.
- Длина: от одного предложения до нескольких абзацев, но не более 5000 знаков (см. п. 5.6).
- Поддержка текста с опечатками, сумбурным изложением, излишней детализацией.

### 8.2. Выходные данные
- Один готовый, структурированный текстовый блок с гипотезами.
- (При необходимости) блок предупреждения о необходимости консультации со специалистом.

## 9. Нефункциональные требования

### 9.1. UI/UX
- **Цветовая гамма:** пастельная, спокойная (светло-бежевый, мягкий голубой, приглушённый зелёный).
- **Типографика:** sans-serif (Inter, Roboto, Open Sans), 16–18px, межстрочный интервал 1.6–1.8.
- **Минимализм:** без лишних графических элементов, без мигающих и пульсирующих анимаций.
- **«Дышащие» отступы** для снижения когнитивной нагрузки.

### 9.2. Адаптивность (Mobile-first)
- Полная адаптация под экраны от 320px.
- Крупные кнопки (минимум 44×44px).
- Клавиатура не перекрывает поле ввода.
- Плавный вертикальный скролл.

### 9.3. Доступность (Accessibility)
- Контрастность текста WCAG 2.1 AA (минимум 4.5:1).
- Доступность с клавиатуры (Tab, Enter, Escape).
- ARIA-атрибуты для скринридеров.
- Видимые фокус-индикаторы.

### 9.4. Производительность
- Время генерации ответа: не более 5–7 секунд.
- Стабильная работа при медленном соединении.

## 10. Этические ограничения и безопасность

### 10.1. Строгие запреты
1. **НЕ ставить диагнозы** — не использовать термины «у вас депрессия», «тревожное расстройство».
2. **НЕ использовать жёсткие шаблоны** — избегать категоричных формулировок.
3. **НЕ заменять терапию** — это инструмент подготовки, а не лечения.
4. **НЕ запрашивать PII** — не спрашивать ФИО, email, телефон, адрес.
5. **НЕ хранить тексты** — тексты пользователей не сохраняются; логируются только технические ошибки без содержания запросов.

### 10.2. Анонимность
- Приложение полностью анонимно.
- Регистрация не требуется.
- Персональные данные не собираются.
- История сессий на сервере **не ведётся**: тексты пользователя не сохраняются ни в базе, ни в логах. Сервер обрабатывает запрос и возвращает ответ, после чего данные не хранятся (см. п. 10.1.5).

### 10.3. Требования к тону
- Бережный, поддерживающий, не осуждающий.
- Осторожный, с модальными конструкциями.
- Уважительный к переживаниям пользователя.
- Профессиональный, но не холодный.

## 11. Архитектура (рекомендации)

### 11.1. Технологический стек
- **Frontend:** React.js / Vue.js + TypeScript
- **Backend:** Node.js (Express/Fastify) / Python (FastAPI)
- **LLM:** OpenAI API (GPT-4) или аналог
- **Стилизация:** Tailwind CSS
- **Деплой:** Docker + облачная платформа (Vercel, Railway, AWS)

### 11.2. API
**POST /api/structure-text**

Request:
```json
{ "text": "строка с текстом пользователя" }
```

Response:
```json
{
  "structuredText": "структурированный текст",
  "hasRedFlags": true,
  "processingTime": 2.3
}
```

Ошибки:
```json
{ "error": "Превышен максимальный размер текста (5000 знаков)" }
```
- `400` — пустой, слишком короткий (< 10 знаков) или слишком длинный (> 5000 знаков) текст.
- `429` — превышен лимит частоты запросов (см. ниже).
- `502` / `504` — LLM недоступна или превышен таймаут (см. п. 5.7).

### 11.3. Защита эндпоинта
- Ключ LLM хранится **только на backend** (в переменных окружения) и никогда не передаётся на frontend.
- Rate limiting: не более **5 запросов в минуту с одного IP**; при превышении — ответ `429` с вежливым сообщением.

## 15. Приложения
