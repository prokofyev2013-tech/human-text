# Промпт для ИИ-агента разработчика: веб-приложение «Текст по-человечески»

## Роль и контекст задачи
Ты — senior full-stack разработчик с опытом создания веб-приложений для чувствительных тематик (mental health, психология). Твоя задача — разработать с нуля веб-приложение «Текст по-человечески» согласно техническому заданию ниже.

## Описание продукта
«Текст по-человечески» — это анонимный веб-инструмент, который помогает клиентам психологов структурировать их сумбурные мысли, вопросы и описания личных ситуаций. Приложение выступает как «безопасное зеркало»: оно сохраняет все факты, имена и цифры, но переформулирует хаотичный текст в четкую, структурированную общую картину с бережными гипотезами о внутренних процессах человека.

**Ключевой принцип:** Приложение НЕ заменяет профессиональную терапию, НЕ ставит диагнозы, НЕ использует жесткие психологические шаблоны. Оно помогает прояснить ситуацию и подготовить запрос для работы с психологом.

## Целевая аудитория
Клиенты психологов и люди, работающие над личностными проблемами, которые испытывают трудности с формулированием своих мыслей из-за:
- Эмоциональной заряженности ситуации
- Сумбура и хаотичности изложения
- Излишней детализации, затрудняющей понимание сути
- Трудностей с вербализацией чувств и переживаний

## Технический стек (рекомендации)
- **Frontend:** React.js или Vue.js с TypeScript
- **Backend:** Node.js (Express/Fastify) или Python (FastAPI)
- **LLM интеграция:** OpenAI API (GPT-4) или аналогичная языковая модель с возможностью тонкой настройки промптов
- **Стилизация:** Tailwind CSS или styled-components для пастельной гаммы
- **Деплой:** Docker + любая облачная платформа (Vercel, Railway, AWS)

## Архитектура приложения

### Frontend
Одностраничное приложение (SPA) с минималистичным интерфейсом.

**Структура главного экрана:**
1. **Шапка** — название «Текст по-человечески» (спокойный, не кричащий шрифт).
2. **Блок дисклеймера** — всегда видимый, но не пугающий текст:
   > «Это приложение помогает прояснить ваши мысли и подготовить вопрос для работы с психологом. Оно не заменяет профессиональную терапию и не ставит диагнозы.»
3. **Поле ввода** (textarea):
   - Плейсхолдер: «Опишите вашу ситуацию или вопрос так, как приходит в голову...»
   - Поддержка текста от 1 предложения до нескольких абзацев, но не более 5000 знаков
   - Счётчик знаков рядом с полем (например, «1240 / 5000»), ввод и вставка длиннее лимита блокируются
   - Автоматическое увеличение высоты поля по мере ввода
4. **Кнопка действия** «Структурировать мысли»:
   - Неактивна (disabled), пока поле пустое или в тексте меньше 10 знаков
   - Активируется при вводе достаточного текста
   - При клике отправляет запрос на backend
5. **Индикатор загрузки** (показывается во время генерации):
   - Спокойный статичный индикатор в пастельных тонах (без пульсации и мигания)
   - Текст: «Проясняю мысли...»
   - Никаких мигающих, пульсирующих или тревожных элементов
6. **Блок результата** (появляется после генерации):
   - Отображает структурированный текст
   - Кнопка «Скопировать текст» (копирует в буфер обмена одним кликом)
   - Кнопка «Начать заново» (очищает поле и результат)
7. **Блок предупреждения** (появляется ТОЛЬКО при обнаружении «красных флагов»):
   - Визуально выделен, но спокойным цветом (не агрессивный красный)
   - Текст: «По указанным темам самостоятельного анализа может быть недостаточно. Настоятельно рекомендуем обсудить это с вашим специалистом или обратиться за экстренной психологической помощью»
   - Опционально: ссылки на телефоны доверия или экстренной психологической помощи

### Backend
RESTful API с одним основным эндпоинтом.

**POST /api/structure-text**
- **Request body:**
  ```json
  {
    "text": "строка с текстом пользователя"
  }
  ```
- **Response:**
  ```json
  {
    "structuredText": "структурированный текст с гипотезами",
    "hasRedFlags": true,
    "processingTime": 2.3
  }
  ```

**Логика обработки на backend:**
1. Принять текст от пользователя и валидировать: не пустой, не короче 10 знаков, не длиннее 5000 знаков (иначе `400` с понятным сообщением).
2. Отправить текст в LLM с carefully crafted промптом (см. раздел «Промпт для LLM»).
3. Получить от LLM структурированный текст + флаг наличия «красных флагов». Ответ LLM — JSON; при битом JSON выполнить один повторный запрос, при повторном сбое — fallback или ошибка.
4. Вернуть результат пользователю.
5. Тексты пользователя НЕ логировать и НЕ хранить; логируются только технические ошибки без содержания запроса.

**Обработка ошибок LLM:**
- Таймаут 30 секунд; при таймауте или ошибке API — до 2 повторных попыток с экспоненциальной задержкой.
- При окончательном сбое вернуть `502`/`504`, пользователь видит вежливое сообщение «Не удалось обработать текст. Попробуйте ещё раз.» с кнопкой повтора.

**Защита эндпоинта:**
- Ключ LLM хранится только на backend (переменные окружения), никогда не отдаётся на frontend.
- Rate limiting: не более 5 запросов в минуту с одного IP, иначе `429`.

## Функциональные требования

### 1. Структурирование текста
- Преобразовать хаотичный, сумбурный ввод в логически связный текст.
- Выделить общую картину ситуации.
- Сформулировать 2–4 осторожные гипотезы о внутренних процессах человека.
- Использовать модальные глаголы: «возможно», «кажется», «может быть связано», «вероятно».
- Избегать категоричных утверждений и диагнозов.

### 2. Строгое сохранение фактов
- Все имена (собственные) должны остаться без изменений.
- Все цифры (возраст, даты, суммы) должны быть сохранены точно.
- Все ключевые факты (места, события, люди) не должны искажаться.
- Пример: если в тексте упоминается «мне 32 года, муж Алексей, мы в браке 7 лет» — это должно остаться в результате.

### 3. Детекция «красных флагов»
Система должна распознавать маркеры:
- Суицидальные мысли или намерения («хочу умереть», «не вижу смысла жить», «лучше бы меня не было»)
- Самоповреждение («режу себя», «хочу причинить себе боль»)
- Острый кризис («меня преследуют», «я в опасности», «не могу дышать от страха»)
- Насилие («он меня бьет», «меня заставляют»)

При обнаружении любого из этих маркеров:
- Генерация структурированного текста продолжается (не прерывается).
- К результату добавляется блок предупреждения о необходимости консультации со специалистом.
- Флаг `hasRedFlags: true` возвращается в response.

### 4. Отсутствие редактирования
- Пользователь НЕ может редактировать сгенерированный текст в интерфейсе.
- Если результат не устраивает, пользователь может только:
  - Скопировать его.
  - Начать заново (очистить поле и ввести новый текст).

### 5. Копирование в один клик
- Кнопка «Скопировать текст» использует Clipboard API.
- После успешного копирования показывается краткое уведомление (toast): «Текст скопирован».
- Уведомление исчезает через 2 секунды.

## UI/UX требования

### Визуальный стиль
- **Цветовая гамма:** Пастельные, спокойные тона.
  - Основной фон: очень светлый бежевый, светло-серый или мягкий голубой (#F5F5F0, #E8F4F8, #F0E6F6)
  - Акцентные элементы: мягкий синий, приглушенный зеленый, нежный фиолетовый
  - Текст: темно-серый, не чисто черный (#2C3E50, #34495E)
- **Типографика:**
  - Шрифт: sans-serif (Inter, Roboto, Open Sans)
  - Размер основного текста: 16–18px
  - Межстрочный интервал: 1.6–1.8
  - Отступы между блоками: большие, «дышащие»
- **Минимализм:**
  - Никаких лишних графических элементов
  - Никаких мигающих, пульсирующих или отвлекающих анимаций
  - Чистое, незагроможденное пространство

### Адаптивность (Mobile-first)
- Полная адаптация под экраны от 320px ширины.
- На мобильных устройствах:
  - Поле ввода занимает всю ширину экрана с отступами 16px
  - Кнопки крупные, легко нажимаемые (минимум 44×44px)
  - Клавиатура не перекрывает поле ввода
  - Вертикальный скролл работает плавно

### Доступность (Accessibility)
- Контрастность текста соответствует WCAG 2.1 AA (минимум 4.5:1).
- Все интерактивные элементы доступны с клавиатуры (Tab, Enter, Escape).
- ARIA-атрибуты для скринридеров.
- Фокус-индикаторы видны и понятны.

## Этические ограничения и безопасность

### Строгие запреты
1. **НЕ ставить диагнозы** — никогда не использовать термины вроде «у вас депрессия», «это тревожное расстройство».
2. **НЕ использовать жесткие шаблоны** — избегать фраз «вы чувствуете X, потому что Y» в категоричной форме.
3. **НЕ заменять терапию** — всегда помнить, что это инструмент подготовки, а не лечения.
4. **НЕ запрашивать PII** — никогда не спрашивать ФИО, email, телефон, адрес.
5. **НЕ хранить тексты** — не сохранять и не логировать тексты пользователя; логируются только технические ошибки без содержания запроса.

### Требования к тону
- Бережный, поддерживающий, не осуждающий.
- Осторожный, с использованием модальных конструкций.
- Уважительный к переживаниям пользователя.
- Профессиональный, но не холодный.

## Примеры ожидаемого поведения

### Пример 1: Обычный запрос
**Ввод пользователя:**
```
Мне 34 года, я работаю программистом уже 10 лет, но в последнее время не могу сосредоточиться на коде, постоянно отвлекаюсь, жена говорит что я стал раздражительным, вчера накричал на сына потому что он громко играл, мне 34 года и я чувствую что выгораю но не знаю что делать, жена Мария предлагает пойти к психологу но я не хочу
```

**Ожидаемый вывод:**
```
**Общая картина ситуации:**
Вы описываете состояние, в котором профессиональная деятельность (10 лет в программировании) перестала приносить удовлетворение и концентрацию. На фоне этого усилилась раздражительность, что повлияло на отношения с близкими — женой Марией и сыном.

**Возможные внутренние процессы:**
- Возможно, вы переживаете этап профессионального выгорания, когда привычная работа перестала давать энергию.
- Кажется, что ваша раздражительность может быть связана с накопленным напряжением, которое находит выход в реакциях на близких.
- Вероятно, существует внутренний конфликт между пониманием необходимости изменений (предложение жены Марии обратиться к психологу) и сопротивлением этому шагу.
- Может быть, чувство вины за срыв на сыне усиливает общее напряжение.

**Для работы с психологом:**
Вы можете обсудить состояние выгорания, трудности с концентрацией, раздражительность в семье и ваше отношение к идее терапии.
```

### Пример 2: Запрос с «красным флагом»
**Ввод пользователя:**
```
Мне 28 лет, последние полгода живу в Москве одна, работа не ладится, друзья все в другом городе, иногда думаю что лучше бы меня не было, не знаю зачем все это
```

**Ожидаемый вывод:**
```
**Общая картина ситуации:**
Вы находитесь в ситуации социальной и профессиональной изоляции в новом городе (Москва), где последние полгода живете одна. Работа не приносит удовлетворения, а привычная поддержка друзей недоступна из-за расстояния.

**Возможные внутренние процессы:**
- Возможно, вы переживаете период глубокого одиночества и потери опор.
- Кажется, что трудности на работе и разлука с друзьями создают ощущение, что вы «выпали» из привычной жизни.
- Вероятно, мысли о том, что «лучше бы меня не было», могут быть связаны с истощением и потерей смысла в текущих обстоятельствах.

**Для работы с психологом:**
Вы можете обсудить чувство одиночества, трудности адаптации в новом городе, профессиональные сложности и ваши переживания о смысле происходящего.

---
⚠️ **Важно:** По указанным темам самостоятельного анализа может быть недостаточно. Настоятельно рекомендуем обсудить это с вашим специалистом или обратиться за экстренной психологической помощью.

Телефон экстренной психологической помощи: 8-800-2000-122 (бесплатно, круглосуточно)
```

## Промпт для LLM (используется на backend)

```
Ты — бережный аналитик, который помогает людям структурировать их мысли о личных ситуациях. Твоя задача:

1. Сохранить ВСЕ факты, имена и цифры из исходного текста без изменений.
2. Выделить общую картину ситуации (2–3 предложения).
3. Сформулировать 2–4 осторожные гипотезы о внутренних процессах человека, используя модальные глаголы: «возможно», «кажется», «вероятно», «может быть».
4. Предложить, что можно обсудить с психологом.
5. Определить, есть ли в тексте маркеры кризиса: суицидальные мысли, самоповреждение, насилие, острый страх.

СТРОГИЕ ЗАПРЕТЫ:
- НЕ ставь диагнозы (не пиши «у вас депрессия», «это тревожное расстройство»).
- НЕ используй категоричные утверждения («вы чувствуете X, потому что Y»).
- НЕ давай медицинских рекомендаций.
- НЕ меняй имена, цифры, факты.

ФОРМАТ ОТВЕТА (строго в JSON):
{
  "structuredText": "структурированный текст в markdown формате",
  "hasRedFlags": true/false
}

Если в тексте есть маркеры кризиса (суицидальные мысли, самоповреждение, насилие), установи hasRedFlags: true, но все равно сформируй структурированный текст.

ИСХОДНЫЙ ТЕКСТ ПОЛЬЗОВАТЕЛЯ:
{user_text}
```

## Критерии приемки (Definition of Done)

Приложение считается готовым, когда:
1. ✅ На главном экране всегда виден дисклеймер о том, что приложение не заменяет терапию.
2. ✅ При вводе текста длиной от 10 до 5000 знаков система выдает один структурированный вариант.
3. ✅ В сгенерированном тексте присутствуют все собственные имена, числа и ключевые факты из ввода без искажения (проверяется на примерах 1 и 2 ниже).
4. ✅ При обнаружении «красных флагов» добавляется рекомендация обратиться к специалисту.
5. ✅ Результат можно скопировать в буфер обмена одним нажатием.
6. ✅ Интерфейс полностью адаптивен под мобильные устройства.
7. ✅ Используется пастельная цветовая гамма без отвлекающих анимаций.
8. ✅ Приложение не запрашивает персональных данных (ФИО, email, телефон).
9. ✅ Время генерации ответа не превышает 5–7 секунд.
10. ✅ Все интерактивные элементы доступны с клавиатуры (accessibility).
